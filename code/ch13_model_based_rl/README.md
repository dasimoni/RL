# Chapter 13 code: Model-Based Deep RL, World Models and AlphaZero/MuZero

Code for [Chapter 13](../../chapters/13-model-based-rl.md). Pure Python 3.11 with NumPy, PyTorch (CPU, one thread), Gymnasium (`Pendulum-v1`) and Matplotlib. Run every script from the repository root. `--quick` is a smoke test that writes nothing; a full run writes PNGs to `figures/` and, for the deep-RL scripts, raw results to `results/*.json`. Seeds are fixed and printed, and every number in the chapter comes from these runs.

## Headline results (full runs, default seeds)

- **Simulation lemma.** The identity (13.2) and occupancy form (13.3) hold to about 1e-15. In the two-state example the bound is nearly attained (error/bound = 0.917 at γ = 0.9, ε = 0.01). On random MDPs the bound held in all 360 cases (checked by an assertion) but was loose by a factor of about 6 at γ = 0.5 (mean observed/bound 0.158, max 0.215) growing to about 800 at γ = 0.99 (0.0012); the observed value error grew roughly linearly in 1/(1−γ) (0.014 at γ = 0.5 to 0.49 at γ = 0.99). With ε_V measured, as (13.5) requires, over the two policies π̂ and π\*, the policy that is optimal in the model lost at most 55% of the 2ε_V allowed by (13.5) (γ = 0.5), and usually nothing.
- **Uncertainty.** On the toy problem the aleatoric estimate matched the true noise on the data (0.192 vs 0.184) and the epistemic part grew five-fold outside the data, but stayed small in a narrow gap between data clusters (0.033 vs 0.026).
- **Compounding error** (1,000 random-policy transitions): open-loop error grew from 0.0028 at 1 step to 0.80 at 50 steps on similar data. On swing-up trajectories the one-step error was already 26× larger, because 14.9% of their transitions hit Pendulum's velocity limit, which the training data never did (one-step error 0.54 there vs 0.0085 elsewhere); the ensemble's disagreement underestimated that error by more than 10×.
- **PETS-lite vs SAC.** After one random episode (200 steps), PETS-lite's first MPC episode was within 3.1 return units of planning with the true dynamics in all 3 seeds; over 27 MPC episodes the median gap to the oracle was −2.1 (25 of 27 within 10). SAC needed about 4,000 steps to reach comparable returns (mean eval return −109 at 4,000 steps) and fluctuated afterwards (mean −201 over evaluations from 4,000 to 10,000 steps). Random shooting with the same budget lost up to 244 per episode to the oracle; a single deterministic network did as well as the ensemble on this deterministic task. With a 5-step horizon, PETS-lite and the same planner with the true dynamics both did about as badly as random torques on the same initial states (Exercise 13): the failure is myopia, not model error.
- **Model exploitation.** With the planner's torque range matched to the data, predicted and realised returns of the chosen plans agreed to within one unit. Allowed to command torques in [−4, 4] (the motor saturates at 2, which the data never show), the chosen plans were over-predicted by 35.3 (D) and 33.2 (PE) on average, against about 8 for unselected random sequences, and 92–98% of them were over-predicted. A disagreement penalty (κ = 1) barely helped (31.5): the members agreed, with a spread of only 1.2. One round of data from the planners' own plans halved the optimism (15.0 and 11.6). The over-predicted plans still realised good returns (−286 vs −304 for CEM with the true dynamics), because the model was wrong about the size, not the direction, of the torque's effect.
- **AlphaZero-lite.** In all 3 seeds the final 100-simulation player has zero losing lines against every possible opponent (as X and as O) and drew all 1,200 games against a perfect player; the raw policy network alone also has zero losing lines. With 128 simulations it chose a minimax-optimal move on 100% of 600 random non-trivial positions (pure MCTS with random rollouts: 97.8%). Without symmetry augmentation the same budget left 1 losing line as O in seeds 0 and 1 (Exercise 14). The snapshot cache made self-play 6–7 times faster than calling the network at every expanded node (`--bench 40`, three runs: 0.26–0.35 s vs 1.8–2.1 s for 40 games).
