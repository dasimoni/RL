# Chapter 03 code: dynamic programming

Companion code for [Chapter 03](../../chapters/03-dynamic-programming.md). Everything is written from scratch in NumPy. SciPy is used only for its LP solver (HiGHS) and sparse matrices, and Gymnasium only to read FrozenLake's transition table `env.unwrapped.P` and to check DP answers by simulation. Run every command from the repository root. `--quick` runs a smoke test that writes no figures. Full mode saves figures to `figures/`.

## Notes

* Terminal states: a transition that Gymnasium marks `terminated` (or that enters a terminal cell) contributes its reward to r(s, a) but **no probability** to P[s, a, :]. The rows of P are therefore substochastic, and every backup gives a continuation value of 0 after termination. This is the model-based form of "bootstrap through truncation, not termination" (see [NOTATION.md](../../NOTATION.md)). Gymnasium's `TimeLimit` is not part of the MDP. `finite_horizon.py` treats it as a horizon.
* `dp.policy_iteration` changes an action only when another one is better by more than a small tolerance. Without this rule PI can cycle between equally good policies (S&B Exercise 4.4).
* `timing_comparison.py` Part B uses its own copy of the algorithms on `scipy.sparse` matrices, so that a sweep costs O(|S||A|b) rather than O(|S|^2|A|). The logic is identical to `dp.py`.
