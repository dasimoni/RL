# Chapter 04 code: Monte Carlo methods

Code for [Chapter 04: Monte Carlo Methods](../../chapters/04-monte-carlo.md). Everything is plain Python and NumPy. No RL libraries are used. Run each script from the repository root. Add `--quick` for a smoke test that takes a few seconds and writes no figures. Full mode saves figures to `figures/`.

`blackjack.py` is shared by the other scripts. It contains:

* a fast simulator of Sutton & Barto's Blackjack (Example 5.1). It follows the same rules as gymnasium's `Blackjack-v1(sab=True)`, verified game by game with shared random streams, and runs about 25 times faster. Like gymnasium, it shows a natural to the player as the state (21, d, usable ace); S&B's text settles naturals at the deal;
* an **exact solver** for the infinite deck. It computes $v_\pi$, $q_\pi$, $q_\ast$, $\pi_\ast$, the best $\varepsilon$-soft policy, the exact expected return $J(\pi)$ of any policy, and its exact win/draw/loss probabilities. With it, every Monte Carlo estimate in this chapter can be checked against ground truth rather than against a longer simulation.

Runtimes were measured on one CPU core of the course machine, one script at a time. The machine is shared, so timings vary by up to about 50% between runs (for example, two full runs of `off_policy_mc_control.py` took 101 s and 148 s).

Running the scripts creates a `__pycache__/` folder here, because they import `blackjack.py` and each other; it is safe to delete.

`on_policy_mc_control.py --glie k0` runs the decaying-$\varepsilon$ variant of Exercise 12, with $\varepsilon_k = k_0/(k_0+k)$. It prints results only, takes about 47 s, and writes no figure. With $k_0=10^4$ the final greedy policies reach $J=-0.0475,-0.0475,-0.0484$. With $k_0=2\times10^5$ they reach $-0.0468,-0.0469,-0.0473$. Both are worse than with constant $\varepsilon=0.1$; the chapter explains why.
